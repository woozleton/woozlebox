WoozleBox Installation

Prerequisites, first-run setup, and model pre-warm

Requirements

WoozleBox is a self-hosted AI toolbox built on Docker Compose. Every GPU-bound service expects a single CUDA-capable NVIDIA card and the NVIDIA Container Toolkit. Testing is done on Windows 11 with an RTX 4090.

Operating System
Windows 11 (WSL2), Linux, or macOS (CPU-only)
Docker
Docker Desktop 4.30+ with Compose v2
GPU
NVIDIA, 24 GB VRAM required (tested on RTX 4090). Smaller cards must pick smaller models and expect swap delays.
Disk
~100 GB free for first-run model downloads + volumes
NOTE WSL2 users need the NVIDIA Container Toolkit installed inside the WSL distribution, and Docker Desktop's "Use the WSL 2 based engine" setting enabled. Verify GPU passthrough with docker run --rm --gpus all nvidia/cuda:12.3.0-base-ubuntu22.04 nvidia-smi.

Install Steps

1
Clone the repo
Grab the source tree and enter the project directory.
git clone https://github.com/woozleton/woozlebox.git
cd woozlebox
2
Clone the Orpheus FastAPI upstream
The tts-api service builds from ./orpheus/, which is gitignored so each install brings its own copy. Run this from the repo root - without it, docker compose up will fail at the tts-api build step.
git clone https://github.com/Lex-au/Orpheus-FastAPI.git orpheus
3
Create your .env file
Create a .env file in the project root and fill in any secrets. The HuggingFace token is required for gated repos (pyannote diarization and SD 3.5 medium). The Tavily key is optional and only used for web search in chat. Defaults for every other env var live in docker-compose.yml and do not need to be set.
# .env
HF_TOKEN=hf_xxxxxxxxxxxxxxxxxxxxxxxxxxxxx
TAVILY_API_KEY=tvly-xxxxxxxxxxxxxxxxxxxx
4
Accept gated-model licenses
Before the first pre-warm, visit each gated repo's HuggingFace page while logged in as the account that owns your HF_TOKEN, and click "Agree and access repository". Skipping this means those models fail to download and the corresponding features (diarization, SD 3.5) will be unavailable.
  • huggingface.co/pyannote/segmentation-3.0
  • huggingface.co/pyannote/speaker-diarization-3.1
  • huggingface.co/pyannote/speaker-diarization-community-1
  • huggingface.co/stabilityai/stable-diffusion-3.5-medium
5
Bring the stack up
The first docker compose up -d builds every service image (image-api, music-api, video-api, notetaker-api, tts-api are the slow ones) and pulls the pre-built ones (Ollama, ChromaDB, nginx, llama.cpp). The tts-init service downloads the Orpheus GGUF (~2 GB) into the tts_models volume once on first start and then exits.
docker compose up -d
TIP You can start using chat immediately - chat only needs Ollama, which pulls the default LLM (qwen3:30b-a3b, ~18 GB) the first time you open chat. Image / music / video / notetaker each download their weights into the shared hf_cache volume the first time you use them, so expect the first generation in each studio to take several minutes. Subsequent uses are instant.
6
Open the web UI and create the admin account
Open http://localhost:8080 in your browser. On first visit you'll see an admin setup screen - create the first account there and you'll be logged in as admin. Subsequent visits show the login screen.
http://localhost:8080
7
(Optional) Pre-pull Ollama models
Ollama pulls qwen3:30b-a3b (main chat, ~18 GB), qwen3:0.6b (utility), and nomic-embed-text (embeddings) on demand the first time each is needed. If you'd rather front-load the download instead of waiting on first use, pull them inside the running Ollama container:
docker exec ollama ollama pull qwen3:30b-a3b
docker exec ollama ollama pull qwen3:0.6b
docker exec ollama ollama pull nomic-embed-text
Once the admin account is created, additional models can also be pulled from the web UI at Settings -> Assistants -> Pull New Model. The UI suggests names from ollama.com/library, accepts any custom Ollama-compatible name, and shows live download progress.

Updating

To pull new code and rebuild only the services that changed:

git pull
docker compose up -d --build

Compose only rebuilds services whose build context changed. Model weights in the hf_cache volume are preserved across rebuilds, so you never re-download what you already have.

Troubleshooting

tts-api build fails with "./orpheus does not exist"

You skipped step 2 of Install Steps. The Orpheus FastAPI upstream is gitignored so each install brings its own copy. Run git clone https://github.com/Lex-au/Orpheus-FastAPI.git orpheus from the repo root, then re-run docker compose up -d.

GPU not detected

If docker compose logs image-api shows CUDA unavailable, verify the NVIDIA Container Toolkit is installed and Docker can see your GPU with docker run --rm --gpus all nvidia/cuda:12.3.0-base-ubuntu22.04 nvidia-smi. On WSL2, make sure you installed the toolkit inside WSL, not on Windows.

Gated repo 403 on first use

If a studio shows a "HuggingFace license not accepted" toast with a repo link, open the link, click "Agree and access repository" while logged into the HuggingFace account that owns your HF_TOKEN, then retry the generation.

Out of VRAM

The gpu-manager service unloads idle models before loading a new one, so you should never hit OOM on a 24 GB card. On smaller cards you may need to avoid Playground v2.5 (the heaviest image model) and stick to SDXL Turbo and SD inpaint.

VRAM orchestration env vars

Three env vars on the gpu-manager service tune VRAM accounting. Defaults suit a 24 GB RTX 4090 running on Windows 11.

Variable
Default
Purpose
VRAM_RESERVED_MB
2500
Subtracted from nvidia-smi total VRAM before budgeting. Covers the Windows desktop compositor, browser, and other background GPU consumers. Raise this on Windows if you run other GPU apps alongside WoozleBox.
IDLE_UNLOAD_MIN
15
Minutes of inactivity before a loaded image / music / video / notetaker / tts service is evicted by the idle-unload timer. Set to 0 to disable.
TTS_FIT_HEADROOM_MB
3500
Extra VRAM headroom when deciding whether the selected chat / code LLM can coexist with Orpheus. If chat_llm + tts + headroom > budget, TTS is evicted, the voice button is disabled, and new TTS requests return HTTP 409 until the user picks a smaller chat model.
CTX_FIT_HEADROOM_MB
1500
Headroom kept free when auto-fitting a chat model's context window. gpu-manager measures each model's per-token KV cost and sets the largest context that fits in VRAM, bounded by the model's native maximum.
CTX_FIT_FLOOR
8192
Never auto-cap a chat model's context window below this many tokens, even on a tight VRAM fit.

First use of a feature is slow

The first time you use image / music / video / notetaker, the backend downloads its model weights from HuggingFace into the hf_cache volume. This can take several minutes per model on a fast connection. The web UI shows a download indicator in the prompt bar while this is happening. Subsequent uses are instant.
